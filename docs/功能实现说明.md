# 钉钉机器人功能实现说明

> 本文档面向非技术背景的读者，用通俗语言解释系统是如何工作的。

---

## 系统是做什么的？

这是一个接入钉钉的智能机器人。用户在钉钉群或私聊中发消息，机器人会自动理解意图，然后去操作后台系统（创建账号、查询数据、导出文件等），并把结果回复给用户。

---

## 消息是怎么处理的？

可以把整个流程想象成一个"翻译 + 执行"的过程：

```
用户发消息
    ↓
机器人收到消息
    ↓
交给 AI 翻译（理解用户意图）
    ↓
翻译成系统能执行的指令
    ↓
去后台系统执行操作
    ↓
把结果回复给用户
```

---

## 各个环节详解

### 1. 接收消息（钉钉 SDK）

钉钉官方提供了一套"消息推送"机制。用户发消息后，钉钉服务器会把消息实时推送到我们的程序。程序一直在后台运行，随时等待接收。

### 2. AI 理解意图（百炼大模型）

这是整个系统最核心的部分。

用户说的话五花八门，比如"帮我查一下张三"、"导出上周的数据"、"新建个账号"——这些都是自然语言，程序本身无法直接理解。

所以我们接入了阿里云的 **通义千问大模型**（百炼平台），把用户的消息发给它，让它帮我们"翻译"成结构化的指令。

**举例：**

用户说：「帮我创建用户 张三 13800138000」

AI 翻译后返回：
```
操作类型：创建用户
参数：姓名=张三，手机号=13800138000
```

用户说：「导出上周的考试记录」

AI 翻译后返回：
```
操作类型：导出考试记录
参数：时间范围=近一周
```

如果 AI 看不懂用户说的是什么，它会返回一个提示，告诉用户缺少什么信息。

### 3. 执行操作（后台系统接口）

拿到 AI 翻译的结果后，程序会根据操作类型去调用对应的后台接口：

| 操作类型 | 做什么 |
|----------|--------|
| 创建用户 | 调用后台接口注册新账号 |
| 搜索用户 | 查询后台数据库，返回用户信息 |
| 导出考试记录 | 从后台拉取数据，生成 Excel 文件 |
| 统计新增学员 | 统计各地区新增人数，汇总成报表 |
| 帮助 | 直接回复功能说明，不调用后台 |

### 4. 回复用户（钉钉消息）

操作完成后，程序通过钉钉接口把结果发回给用户。

- 文字结果（如用户信息、统计数据）：直接发文字消息
- 文件（如 Excel 导出）：上传到钉钉，以文件形式发送

---

## 异常情况怎么处理？

系统设计了多层保护，避免出错时影响用户体验：

| 情况 | 处理方式 |
|------|----------|
| AI 服务暂时不可用 | 回复"解析服务暂时不可用"，提示用户稍后重试 |
| AI 没理解用户意图 | 回复 AI 给出的提示，引导用户补充信息 |
| 后台接口报错 | 回复具体错误原因（如"手机号已注册"） |
| 导出数据量大 | 先回复"正在处理"，后台异步执行，完成后再发文件 |

## 系统需要哪些配置才能运行？

运维人员启动程序时需要提供以下参数：

| 参数 | 用途 |
|------|------|
| `ding.appKey` / `ding.appSecret` | 钉钉机器人的身份凭证，用于接收消息和发送回复 |
| `sys.username` / `sys.password` | 后台系统的登录账号，用于执行创建用户、导出数据等操作 |
| `bailian.apiKey` | 阿里云百炼平台的 API 密钥，用于调用 AI 翻译功能 |

> 如果没有配置 `bailian.apiKey`，AI 翻译功能不可用，机器人会提示"NLU 功能未启用"。其他功能不受影响。

---

## 数据安全说明

- 用户发送的消息只用于理解意图，不会被存储
- 后台系统的账号密码通过启动参数传入，不写在代码里
- AI 接口调用通过 HTTPS 加密传输

```
                  └──────────────┘  └──────────────┘  └──────────────┘
```
